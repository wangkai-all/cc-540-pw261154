# 机械表采集：换表工单迟到 × 读数回拨重传（本地演示）

零依赖，仅使用 Node.js 内置模块（`node:http` / `node:fs` / `node:path` / `node:test`）。

## 启动

```bash
node src/server.js            # 默认端口 3000
PORT=4567 node src/server.js  # 自定义端口，读取环境变量 PORT
```

服务只绑定 `127.0.0.1`，启动后打开 http://127.0.0.1:<PORT> 。

## 测试

```bash
node --test
```

## 业务规则与证据分离

| 情形 | 证据 | 处理 |
| --- | --- | --- |
| 换表（新表从 0 起算） | 换表工单 `workOrder` | 更新表计关系段：旧段封口、新段启用；撤回工单能解释的“读数掉零”误判，日用量按两段重算 |
| 读数回拨 | 同表相邻读数对（prev → current，差值为负） | `READING_ROLLBACK` 异常，日用量钳为 0，**绝不产生负用量** |
| 重传/订正 | 同一 `(meterId, date)` 的版本链 `version`（大者生效，历史版本保留） | 以生效版本重算，回拨同样钳 0 |
| 工单迟到、读数先到 | 读数缺表计关系 | 先误判 `SUSPECTED_DROP_ZERO`，用户归并挂起（provisional）；表计层面仍按表号独立累计 |

两层累计口径：

- **按表号独立累计**：只在同一 `meterId` 的相邻读数间做差，新表首读数从 0 开始，不与旧表读数跨表相减。
- **按用户连续归并**：依据表计关系段把各表日用量挂到用户；换表日 = 旧表尾段用量 + 新表首段用量。

不变式（引擎内有守卫，违反即抛错）：任何表计日用量、用户日用量均 `usage >= 0`。

## 网页操作

1. **接入换表前后读数** —— 工单尚未到达，新表 `M-NEW-1` 读数被误判“读数掉零”，归并挂起。
2. **补交换表工单** —— 误判撤回（异常台账保留 withdrawn 轨迹，证据指向工单），关系拆成换表前/后两段，挂起记录转正式。
3. **重传样例（读数回拨订正）** —— v2 版本生效，11/19 读数 120 → 118，重算后无负用量。

页面业务结果区带 `data-evidence-result` 属性，每次处理后同步写入结构化结果（表计/用户用量、异常状态、是否存在负用量），便于核对操作前后内容；下方“用量修订记录”面板展示快照间的前后差异。所有结果均由服务端引擎实际处理返回。

## 目录

```
src/
  engine.js          核心引擎：读数/工单接入、全量重算、异常台账、修订对比
  synthetic-data.js  合成数据（含迟到工单、重传回拨、异常样例）
  server.js          HTTP 服务与演示端点（127.0.0.1，读取 PORT）
  public/index.html  演示页面
test/
  engine.test.js     node --test 用例：正常/异常/证据分离/HTTP 冒烟
```

## API

- `GET  /api/state` 当前快照（关系段、表计/用户日用量、异常、读数版本链）
- `GET  /api/revisions` 各次处理的修订差异
- `POST /api/demo/ingest-readings` 操作①
- `POST /api/demo/ingest-work-order` 操作②
- `POST /api/demo/retransmission` 操作③
- `POST /api/reset` 重置为基线数据
